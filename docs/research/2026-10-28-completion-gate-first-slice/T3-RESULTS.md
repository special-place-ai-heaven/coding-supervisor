# T3 results: Claude Code enforcement investigation

Date: 2026-10-29. Harness: `claude --version` = `2.1.312 (Claude Code)`. Status: investigation complete; no adapter built, no core change, no un-block. Hook behaviour is version-dependent; every claim below is tied to this version and this date.

## Adapter mode this evidence supports (one line)

**Enforcing on three named paths, advisory/audit everywhere else:** enforcing at (1) `PreToolUse` denial of a tool call while the gate is not accepting, (2) `Stop` refusal of a turn whose final message claims completion while the gate state is not `completed`, bounded by the harness's 8-consecutive-continuation cap and the `stop_hook_active` flag, and (3) `SubagentStop` refusal of a worker's unsupported handback, same bound; advisory/audit at `PostToolUse` result annotation or replacement (foreground dispatch only), at background-dispatch results (observable only through `SubagentStop` and the task-notification prompt), and at the acceptance moment itself, for which no hook event exists.

## Setup

- Fixture: `fixtures/claude-code-enforcement/` with its own `.claude/settings.json` (hooks on `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `SubagentStart`, `SubagentStop`, `Stop`), a throwaway Python handler `hooks/capture.py` (Python 3.14.4), a per-session policy `hooks/policy.json`, a controlled fake worker (`.claude/agents/fake-worker.md` and the same definition in `hooks/agents.json` passed with `--agents`), `candidate.txt` as the candidate, `gate-state.json` holding `{"state": "verifying"}` for every run.
- Every hook event runs the same handler, which appends the payload (strings truncated to 300 characters, no credentials) to `captures/<session_id>.events.jsonl` and then applies the configured decision. Raw captures and the `--debug-file` logs stay under the fixture; the debug logs are git-ignored (about 400 KB, environment detail), the event captures and receipts are committed.
- Sessions were run through Terminal Commander `run_and_watch` as `claude -p … --model sonnet --output-format json --setting-sources project --settings <fixture settings> --agents <fixture agents> --permission-mode acceptEdits --session-id <fixed uuid> --debug-file <fixture captures> --max-turns N`, cwd = the fixture, with the inherited `CLAUDECODE`, `CLAUDE_CODE_SUBAGENT_MODEL`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CODE_ENTRYPOINT` cleared and `CLAUDE_PROJECT_DIR` set to the fixture. `--setting-sources project` kept the user-level hooks (Jev prompt hook, md-gate, doc-staleness) out of every run. Chair model `claude-sonnet-5-5`, worker `claude-haiku-5-5`.
- Workspace trust: per the hooks reference, a `-p` session treats the folder as trusted and runs the project's settings-file hooks; an interactive session runs them only after the trust dialog is accepted. The live chair sessions this adapter targets are interactive sessions in trusted folders.
- Hook command form on Windows: `python E:/project/.../hooks/capture.py` (shell form, forward slashes); every hook finished with status 0 in 280 to 510 ms per the debug log lines `Hooks: <Event>:<matcher> [...] finished with status 0 (Nms)`.

Known flaw in the throwaway handler, left as evidence rather than tuned: its "claims done" regex also matched "not done", so in T1, T2, T3, T4 and T8 the `Stop` block fired on messages that already refused completion. The chair handled every such block correctly, but a real adapter must parse the claim, not grep for a word.

## Reading for T4 (the adapter)

- The hard refusal of execution is `PreToolUse` only. `Stop` and `SubagentStop` refusals are strong but bounded by the harness cap and need the chair's cooperation after the reason; both held in every run here with a sonnet chair.
- Receipts can be captured at `PostToolUse` for `Bash`/`PowerShell` (command, exit code via `tool_response`) and the candidate identity can be observed at `PostToolUse(Write|Edit)` and from `tool_response.bashEditDiff`; neither was exercised here beyond the `Write` payload shape.
- For background dispatch the adapter must listen on `SubagentStop` and treat the `<task-notification>` prompt as the delivery point.
- `--setting-sources project` plus `--settings <file>` is a clean way to run an isolated adapter fixture without touching user settings.
