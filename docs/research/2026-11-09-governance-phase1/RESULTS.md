# Barrier matrix results (WP8)

The 20 cases of spec section 9, each demonstrated by named tests that already exist in this
repository. No source or test was changed for this record.

What was run: for each case, `cargo test -p <package> --test <file> -- <test names> --exact --nocapture`,
started through `docs/research/2026-11-09-governance-phase1/evidence/run-case.mjs`, which sets
`CARGO_TARGET_DIR=C:\Target\coding-supervisor\main\target` and points `TMP` and `TEMP` at
`C:\Target\coding-supervisor\matrix\tmp`. Every test file used here makes its throwaway git
repositories and state folders under `std::env::temp_dir()`, which reads `TMP` on Windows; the
tests remove them when they finish, the folder was empty afterwards, and it was then deleted. No
case touched a real working tree. Every run
was started through Terminal Commander, one cargo job at a time.

Where: Windows 11 only, on commit `41f207ce75b99f418aaa98ad04aa309256a71cda` (origin/main on
2026-11-11). The commits on this branch add only files in this folder. Free space on C: before the
first cargo run was 73.6 GB.

How to read a row:

- Most evidence is a replay test: the real hook code, or the real `supervisor` binary, judges
  made-up hook payloads against a throwaway repository and state folder. It is not a live Claude
  Code session.
- `exit` is the exit code of the recorded test run (for a case with several commands, the first
  nonzero, else 0). 0 means every named test ran and its assertions held. It does not mean the
  barrier is complete. The `actual` column says how much of the case the tests show, in one of
  three words: Shown, Partly shown, Not built.
- For every case the output was checked to hold one `test <name> ... ok` line per named test.
- `output.txt` holds the combined output with the user profile, the target folder, the fixture
  folder and the worktree replaced by placeholders; trailing blanks and carriage-return progress
  lines are removed. `run.txt` holds each command and its exit code. Cases 1 to 15 were recorded
  before one change to the runner that only quotes an argument with spaces when the command is
  printed; none of their arguments has a space.

## Deferrals and gaps

- Case 1, partly shown: blocked only once a prompt is registered; a project with no prompt and no
  contract is advisory. No test sends a Write to such a project, and the denial reason is not
  asserted.
- Case 2, partly shown: approval is recorded, never checked. Refusing an unapproved contract is
  not built.
- Case 4, partly shown: traversal and link escapes are refused at strict only; at enforce no test
  shows them refused or caught later.
- Case 5, partly shown: no default protection for secrets or lockfiles. `deny_path` refuses
  writes at strict only; `protected_paths` covers deletion only.
- Case 6, partly shown: only Write, Edit, MultiEdit and NotebookEdit into the base checkout are
  refused; shell commands and MCP write tools are not.
- Case 8, partly shown: no test makes the created worktree's base differ from the contract's
  base (the check exists in the source); an agent proposal can bind an existing worktree.
- Case 12, partly shown: no reviewer timeout concept; an undecided review counts as no review. The
  outstanding-reviewer path is covered only in pieces.
- Case 13, not built: no local commit barrier. Export refuses and CI requires a receipt instead.
- Case 14, partly shown: no per-artifact hashes.
- Case 15, partly shown: a bundle with its `signature` object removed is not tested.
- Case 18, partly shown: a crashed hook process gives no decision; blocking then depends on the
  harness, and Claude Code lets a Stop or SubagentStop through.
- Case 19, partly shown: an agent proposal can bind an existing worktree, also one a person's
  start created.
- Cases 3, 16, 17 and 20 are shown with the declared limits named in their rows (write-time scope
  refusal at strict only, CI cannot see hooks, processes not capped, submodules).

## Not verified

- Linux: every run here was on Windows. The unix branches (symlinks instead of junctions, file
  modes) were not compiled or run for this record.
- A live Claude Code session: no case was run through a real harness; whether Claude Code honours
  `onFailure: block`, registers every prompt, and sets the hook `cwd` as the tests assume is not
  measured here.
- The CI side of case 16 is read from the GitHub API for an earlier run; this branch's own CI run
  is not part of the record.
- No case needs the central server, so no row is N/A.
