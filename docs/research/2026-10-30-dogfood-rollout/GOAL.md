## Decisions to settle in phase 1

Recommend one explicitly shared active task per canonical worktree, serialized across Claude/MCP sessions; this matches today's shared project state and avoids accidental competing task activation. Confirm through tests rather than treating the recommendation as implemented behavior. Task-level identities must still prevent late-session writes to a successor task.

Choose the smallest crash-safe transaction/locking strategy consistent with the standard-library-only core; justify any adapter dependency. Define identity normalization and migration before changing state layout. A collision must require explicit selection, never first-match adoption. Specify exact lifecycle command names and terminal-state dispositions after inspecting existing CLI/MCP conventions.

Action-policy work is bounded to explicit configured cases and actual interception surfaces. It does not promise comprehensive shell semantic analysis, an OS sandbox, a new Codex enforcing adapter, deployment/publishing controls outside observed routes, automatic activation in eight projects, new routing/model selection, a UI, or a standalone agent loop engine. Missing coverage is a named gap; it is not a reason to insert blanket approval prompts.
